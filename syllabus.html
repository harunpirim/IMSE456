How this course runs

Two sessions a week, and they do different jobs.

Tuesday is concept and case. The chapter’s ideas, then a short case with a decision in it and one question worth arguing about. You leave with an assignment.

Thursday is studio, and it is hands-on and individual. Every student works at their own machine on the same three movements:

  1. Build — 25 minutes. You implement the concept yourself: write the critical-path passes in Python, build the earned-value model, direct an agent to draft a work breakdown structure. No professional software yet. You cannot hide behind a black box you had to construct.
  2. Use — 20 minutes. The same project, in ProjectLibre, Smartsheet, Taiga or Power BI — the tools you will meet in industry, met while you already know what they are doing underneath.
  3. Reconcile — 15 minutes. The two disagree. They always do. Find the difference, explain it, decide which is right. This is the graded part, because it is the only part a machine cannot check for you.

A five-minute peer check closes the session: a neighbour runs your “done looks like” checklist against your screen. It is not grading, it is catching.

Studios are individual. The project is a team.

The mechanics have to be in your hands — in a team studio one person drives the software and the others watch, then discover in Week 11 that they cannot do a backward pass. The final project is where collaboration genuinely matters, and that is where you will work in a team of four or five. Nobody free-rides on the mechanics; nobody does the project alone.

Course description

Project management as it is actually practised: the quantitative core — work breakdown, critical path, PERT, resource levelling, crashing, earned value — alongside adaptive delivery and flow metrics, with hybrid treated as the default real-world case rather than a compromise. The course argues from empirical evidence rather than from convention.

Running through every week is an AI layer. You will generate project artifacts with a model, then write the code that checks them; specify and build agents; and, in the final project, govern one that maintains a live artifact — and report what it got wrong.

Course objectives

By the end of the course you can:

  1. Decide which delivery approach fits a given project and defend the choice against a specific alternative.
  2. Build and interpret the core quantitative artifacts: WBS, CPM network, PERT distribution, resource-levelled schedule, crash analysis, EVM report.
  3. Run the adaptive artifacts: product backlog, sprint mechanics, cumulative flow diagram, Little’s Law.
  4. Read the evidence critically — distinguish a base rate from a vendor statistic.
  5. Diagnose a failing project and propose interventions ranked by expected effect, not by convention.
  6. Specify, build and govern an AI agent that maintains a live project artifact, and state what it got wrong.

Additional expectations for students enrolled in IMSE 656

Students enrolled under the graduate number complete the same components at a higher level of expectation:

  • Conceptual assignments include an additional short-answer section requiring a claim grounded in one of the primary sources on the source shelf.
  • Studio assignments require the reconciliation paragraph to cite the mechanism, not only the symptom — which algorithm or formula choice produces this difference, with a reference.
  • Final project includes a methods justification: the choice of delivery approach, estimating method and control mechanism defended against the empirical literature, with citations.
  • Final presentation includes a five-minute defence against a challenge drawn from the counter-evidence for the position taken.

If you work on lab computers only, this course still works

Two tools are local installs; everything else runs in a browser. Where an install is a problem, each lab sheet gives you a substitute: Smartsheet in place of ProjectLibre, and the Gemini API from Colab in place of Antigravity. Nothing is lost and nothing is graded differently.

Software installation is never homework. Week 1’s access form asks which machine you will work on and which AI tools you can reach; your answer decides which version of every later lab sheet you receive. It has no effect on your grade.

Save nothing to a local disk. Lab machines are wiped on reboot and laptops get left at home. Set up a cloud folder in Week 1 and keep everything there.

Late work

Conceptual assignments close at the posted time and do not reopen; the lowest score is dropped to absorb one missed set. Studio assignments lose 10% per calendar day to a floor of 50%, for five days, after which they are not accepted — and the two lowest are dropped, which is your margin for a bad week. Final project milestones are firm because a partner organization is waiting on them; contact the instructor before the deadline if a milestone is at risk.

Feedback turnaround

Conceptual assignments are graded automatically. Studio assignments are returned within seven days. Project milestones within fourteen.

Use of Generative Artificial Intelligence

Generative AI use in this course is permitted and expected, within the parameters below. This section is the course’s AI policy under NDSU Policy 335: Code of Academic Responsibility and Conduct. Use outside these parameters is academic dishonesty and is handled under that policy.

Much of this course is about using these tools well and knowing when they are wrong. That is a learning objective, not a concession.

Approved tools

Gemini, Google Antigravity, the Gemini API supplied through the course notebook, and Microsoft 365 Copilot are approved for all permitted uses without further request. Any other general-purpose assistant is approved on the same terms provided you name it in your disclosure. Anything that is not a general-purpose assistant — a tool that completes assignments for you, or a service you would have to send course material to — ask first.

Every student has access to Gemini and Antigravity, and the instructor supplies API keys to anyone who needs them, so no graded work in this course depends on being able to buy a subscription.

How much AI, on which assessment

Each assessment carries a level from the Generative AI Acceptable Use Scale (Perkins et al., 2024). The level is repeated on every lab sheet and assignment so you never have to guess.

Assessment Level What that means here
Midterm examination 1 · Prohibited Closed book, closed notes, no computers or phones. The reasoning this tests is the reasoning you need when the tool is unavailable or wrong.
Conceptual assignments (CA1–CA8) 1 · Prohibited during the attempt These are quizzes. Use AI freely to study — the Tutor prompts in AI Studio are built for it — but not while the assessment is open.
Studio assignments (SA1–SA14) 4 · Full use with documentation Generate freely, including the code. Every quantitative result arrives with the check that proves it, and the reconciliation paragraph must be your own reasoning.
Final project (FP1–FP4) 5 · Full use with human oversight You are required to build and run an agent that maintains a live project artifact, and to report what it got wrong and how you caught it.

The three rules

  1. Label it. Any submitted artifact a model produced or substantially drafted says so, names the tool, and includes the prompt or a shareable link to the conversation.
  2. Verify it. Every quantitative result a model generates is submitted with the code or hand calculation that checks it. A number you cannot verify is a number you did not produce. The check is graded, not the output.
  3. Own it. You are responsible for everything you submit, including the parts a model wrote. “The model said so” is not a defence — not here, and not in a project review.

How to disclose

Append this to any submission where AI was used. It takes two minutes and its absence is what turns permitted use into a violation.

AI acknowledgement. I used [tool and version] for [what — e.g. drafting the WBS, writing the forward-pass code, generating counter-arguments]. Prompt or transcript: [link or attached screenshots]. What I changed after reviewing its output: [specific edits]. What it got wrong: [or “nothing I found”, if that is honestly the case]. I have verified every quantitative result in this submission and the verification is included.

The requirements, in short

  • Acknowledge any significant AI contribution in submissions.
  • Verify all AI-generated content for accuracy.
  • Use AI ethically; violations constitute academic dishonesty.
  • AI is forbidden for quizzes and tests — the midterm and the conceptual assignments.

Data, confidentiality and privacy

This matters more here than in most courses, because your final project involves a real organization’s information.

  • Do not put a partner organization’s confidential information into any AI tool. Costs, contracts, customer data, unreleased plans, anything they asked you to protect. Generalize the problem or use synthetic numbers instead. If you are unsure whether something is confidential, it is.
  • Do not put anyone’s personal information into an AI tool — classmates’, a partner’s staff, your own beyond what you would post publicly.
  • Do not upload another student’s work. Their submissions are their educational records.
  • If a partner asks for a written commitment about AI use, bring it to the instructor before you agree to anything. Do not sign on behalf of NDSU.

Instructor use of AI — disclosure

You are being asked to label, verify and own your AI use. The same standard applies to the person teaching you, so here is exactly how AI was used to build this course.

What AI did. Working from my own outlines, notes and the textbook’s chapter structure, I used generative AI to help organize the course: to sequence the sixteen weeks against Larson’s chapters and argue about where the displacement should fall; to draft and edit lecture notes, the mini-cases you read on Tuesdays, and the studio lab sheets you work from on Thursdays; to generate the studio datasets and compute every answer key programmatically; to draft rubrics and the “done looks like” checklists; and to build this website.

What AI did not do, and will not do.

  • It does not grade you. No AI system assigns or recommends a mark in this course.
  • Your work is not uploaded to any third-party AI system, for grading or for any other purpose. Your submissions are educational records under FERPA and they stay in Blackboard.
  • It does not decide anything. Every sequencing choice, assessment weight, rubric criterion and final grade is mine.

What I verify. Every factual claim, empirical figure and citation in these materials is checked against a primary source before it is published — the sources are listed in AI Studio so you can check them too. Every numerical answer key is computed in code rather than by hand, precisely because a hand-worked key is where errors hide and an error in a key is worse than an error in a lecture.

Where you can see it. This site is public and so is the repository that builds it. If you want to see how a course is actually assembled, including the parts a model drafted, you can read the source. That transparency is the point: I am asking you to show your work, so I show mine.

If AI use in this course changes — a new tool, a new use — it will be announced on Blackboard and this section updated. If you think something here was AI-generated and is wrong, tell me. You will be right often enough to make it worth asking, and finding it is exactly the skill this course is trying to build.

What this course deliberately does not cover

  • PMP exam drilling. The exam changes; the reasoning does not.
  • Software menu tours. You will use six tools, but no lecture time goes to menus — the studio teaches the tool by making you build what it does first.
  • The full process catalogue. You learn the shape of a process standard and how to look things up. Memorizing inputs-tools-outputs is the lowest-value activity in project-management education.
  • Scaling frameworks in depth. One segment on why they exist and why the evidence is thin.
  • Six Sigma and lean manufacturing. Adjacent field, separate course.
  • Contract law. Contract types and incentive structure are covered; the law is not.
